# 웹캠 기반 인술 대전 게임 기획 정리 v6

## 0. 문서 목적

이 문서는 웹캠으로 손 인을 인식해 술법을 발동하는 팬 프로젝트의 **현재 기준 단일 기획 문서**다. v6는 v5.2의 single source of truth 구조를 유지하면서, 고증 검증 결과를 반영해 술법 시퀀스의 출처 관리 원칙을 명문화한다.

핵심 콘셉트는 다음과 같다.

> 플레이어가 실제 손으로 인을 맺어 술법을 조합하고, 상대의 손동작과 차크라 흐름을 읽어 대응하는 웹캠 기반 인술 대전 게임.

### v5.2 대비 주요 변경

```text
1. 호화구의 술 시퀀스 후보 표를 출처 명시형으로 재작성 (§6.1)
2. 호화구의 게임 적용안을 5가지 검증된 variant 구조로 확장 (§6.2)
3. 고증 관리 원칙에 "모든 공식 매체 = 정전, canonStatus로 구분" 원칙 명문화 (§18)
4. 기획 변경 이력 명시
```

## 1. 게임 방향

이 게임은 단순 손모양 맞추기가 아니라, 원작의 전투 문법인 **차크라, 인, 술법 시퀀스, 속성 상성, 정보전, 숙련도, 카운터**를 게임 규칙으로 번역하는 것을 목표로 한다.

핵심 재미는 다음 네 가지다.

```text
1. 손으로 직접 인을 맺는 피지컬 재미
2. 술법 시퀀스를 외우고 빠르게 입력하는 숙련 재미
3. 상대 손동작을 보고 술법을 읽는 정보전
4. 속성, 방어, 카운터, 차크라 관리에서 나오는 전략성
```

---

## 2. 핵심 플레이 루프

```text
1. 플레이어가 사용할 술법 세트를 고른다.
2. 전투가 시작된다.
3. 상대의 거리, 차크라, 손동작, 캐스팅 상태를 본다.
4. 사용할 술법의 인 시퀀스를 실제 손으로 입력한다.
5. 시스템이 인 순서, 정확도, 안정성, 전환 속도를 판정한다.
6. 술법이 발동된다.
7. 상대는 회피, 방어술, 속성 카운터, 체술 끊기, 페이크로 대응한다.
8. HP 또는 차크라가 먼저 무너진 쪽이 패배한다.
```

## 3. 고증 우선 원칙

모든 술법을 인 시퀀스형으로 만들면 고증이 깨진다. 술법별 발동 방식을 분리해야 한다.

| 발동 타입 | 기술 enum | 설명 | 게임 입력 방식 |
|---|---|---|---|
| 인 시퀀스형 | hand_seal_sequence | 호화구, 수룡탄 같은 전통 인술 | 손 인 순서 입력 |
| 무인 차크라 제어형 | chakra_control | 나선환처럼 인 없이 차크라 형태를 제어 | 손바닥 유지, 회전 게이지, 압축 판정 |
| 체술형 | taijutsu_motion | 인 없이 빠르게 접근/공격 | 키 입력, 자세, 짧은 제스처 |
| 환술형 | genjutsu_trigger | 오감/인지 교란 | 시선, 손가락 트리거, UI 교란 |
| 분신/기만형 | clone_or_deception | 분신, 변신, 바꿔치기 | 정보전, 회피, 가짜 입력 |
| 소환/계약형 | summoning_contract | 피, 계약, 차크라량 기반 | 긴 준비, 고비용, 큰 보상 |
| 봉인/결계형 | sealing_or_barrier_formula | 공간/상태 제약 | 장판, 디버프, 차크라 제한 |

위 분류는 게임 입력 방식을 기준으로 한 자체 분류이며, 원작의 닌주츠/타이주츠/겐주츠 3대 분류와는 다른 축이다. 원작 3대 분류와의 매핑은 후속 검증 항목이다.

## 4. 상대 손 공개와 정보전 UI

이 게임의 정보전은 **글자 UI를 읽는 것**이 아니라 **상대 손을 읽는 것**이 핵심이다. 다만 온라인 경쟁 환경에서는 원본 웹캠 영상을 그대로 주고받으면 부정행위와 개인정보 문제가 생긴다.

### 4.1 모드별 정보 공개

| 모드 | 상대 손 정보 | 의도 |
|---|---|---|
| 로컬/친구전 | 실제 손 영상 허용 | 재미와 직관성 우선 |
| 수련장/초보 | 손 영상 + 인 이름/아이콘 | 학습 우선 |
| 일반 온라인 | 손 실루엣/랜드마크 + 캐스팅 스트립 | 손 읽기 유지 + 개인정보/치팅 완화 |
| 랭크전 | 정규화된 손 실루엣 + 최소 UI | 경쟁 공정성 우선 |
| 관전/리플레이 | 전체 정보 표시 | 이해/분석/바이럴 우선 |

### 4.2 디자인 결정

```text
경쟁 모드에서 양쪽이 서로의 손 정보를 보는 것은 의도된 정보전이다.
단, 원본 웹캠 영상이 아니라 정규화된 손 실루엣 또는 캐스팅 스트립을 기본 표현으로 한다.
```

### 4.3 두 정보 채널의 역할

| 채널 | 의미 | 정보 성격 |
|---|---|---|
| 손 실루엣 | 지금 상대가 어떤 손동작을 만들고 있는지 | 연속적, 추측 정보 |
| 캐스팅 스트립 | 확정된 인이 어디까지 입력되었는지 | 이산적, 확정 정보 |

정리하면 다음과 같다.

```text
UI 표시:
- 손 실루엣은 전환 중 움직임까지 흐릿하게 보여준다.
- 캐스팅 스트립은 확정된 인만 명확히 보여준다.

데이터 기록:
- 캐스팅 스트립에는 확정된 인만 기록한다.
- 전환 중 추측 정보는 확정 기록으로 남기지 않는다.
```

### 4.4 정보 비대칭 처리

```text
1. 전환 중 손동작은 흐릿한 실루엣으로만 보인다.
2. 캐스팅 스트립에는 확정된 인만 기록한다.
3. 상대에게 보이는 정보는 100~200ms 정도의 고정 지연을 둘 수 있다.
4. 지연은 양쪽에 동일하게 적용해 정보 비대칭을 만들지 않는다.
5. 랭크전에서는 원본 영상이 아니라 랜드마크 기반 실루엣만 사용한다.
```

## 5. 숙련도와 인 단축

인 시퀀스형 술법은 최대 Lv.3까지를 기본 게임 레벨로 두며, 일부 술법은 자료집/팬북에 추가 시퀀스가 있을 경우 Lv.4 전설형으로 확장 가능하다. 일반 PvP에서는 최소 3개 인을 유지하는 방향을 우선 검토한다. 단, 원작상 원래 인이 없는 술법은 별도 차크라 제어형으로 분류한다.

### 5.1 hold 시간은 숙련도 보정으로 쓰지 않는다

hold 시간은 레벨에 따라 줄이지 않는다. 이 게임의 실력 요소 중 하나는 **카메라가 안정적으로 인식할 수 있게 손을 만드는 능력**이다. 따라서 hold 시간은 게임 밸런스 요소가 아니라 모든 플레이어에게 동일하게 적용되는 기술적 안정화 기준으로만 둔다.

### 5.2 Lv.3의 역할

Lv.3는 반드시 "더 짧은 인"이 아니라 **운용 숙련도**로 정의한다. 아래 항목은 전체 후보이며, 각 술법은 이 중 일부만 선택해서 적용한다.

```text
- 후딜 감소
- 차크라 효율 증가
- 실패 페널티 감소
- 중간 캔슬 가능
- 페이크 인 전환 가능
- 같은 시퀀스에서 차지/강화 분기 가능
- 카운터당했을 때 회복 가능성 증가
```

## 6. 호화구의 술 고증 처리

한국식 표기인 사·미·신·해·오·인은 12간지/십이지의 지지 표기다. 여기서 마지막 `인`은 인술의 인(印)이 아니라 호랑이를 뜻하는 지지 `寅`이다.

### 6.1 검증된 시퀀스 후보 (β 원칙 기반)

호화구의 술 인 시퀀스는 단일 정답이 아니다. 공식 매체별로 서로 다른 시퀀스가 묘사되었으며, 본 프로젝트는 이를 모두 정전으로 인정하고 출처를 명시한다.

| 매체 | 인 시퀀스 | 출처 상세 | canonStatus |
|---|---|---|---|
| 만화 일반 시전 | 사 → 미 → 신 → 해 → 오 → 인 (6개) | 우치하 일족 전반의 사용 사례 (사스케 첫 사용, 후가쿠, 이타치, 마다라, 오비토 등) | manga |
| 시푸덴 4화 카카시 | 6개 초과 (정확한 개수 불명) | 카카시가 빠르게 시전, 일반적인 6개보다 많은 인 사용 | anime |
| 시푸덴 15화 이타치 | 해 → 오 → 인 (3개) | 이타치 vs 카카시/나루토/사쿠라/치요 전투 | anime |
| 린노쇼 (1st Databook) | 오 → 인 (2개) | 2002년 7월 슈에이샤 발행 공식 데이터북 | databook |
| 효노쇼 (1st Fanbook) | 인 (1개) | 1st Fanbook. 데이터북 시리즈와는 별개 자료 | databook (팬북) |

핵심 원칙:

```text
β 원칙: 매체별로 다르게 묘사된 시퀀스는 모두 공식으로 인정한다.
각 시퀀스는 출처(canonStatus, sourceReference)와 함께 게임에 포함된다.
어느 한 시퀀스를 "표준", 다른 시퀀스를 "단축"이라고 강제로 위계 매기지 않으며,
게임 레벨(Lv.1~Lv.4)은 인 개수와 게임 운용 편의를 위한 게임 디자인 분류일 뿐이다.
```

추가 메모:

```text
- 만화에서는 우치하 일족만 호화구를 사용하며, 애니에서는 비우치하도 사용한다.
- 우치하 일족에게 호화구는 성인식 술법이다.
- 시푸덴 4화 카카시 시퀀스는 화면상 인 개수가 불명이므로 게임 variant로 직접 구현하지 않고,
  "비우치하 사용 사례" 메타 정보로만 데이터에 보유한다.
```

### 6.2 게임 적용안

5가지 검증된 시퀀스를 게임 레벨로 매핑한다. 각 variant는 sourceReference 메타데이터를 보유하며, 게임 내 도감/툴팁에서 출처가 노출된다.

```text
호화구의 술 — 게임 variant 구조

Lv.1 표준형
시퀀스: 사 → 미 → 신 → 해 → 오 → 인 (6개)
출처: 만화 (canonStatus: manga)
sourceReference: "우치하 일족 일반 사용 — 사스케 첫 사용 등"
MVP 활성화: MVP 1 (수련장 핵심 시퀀스)

Lv.2 단축형
시퀀스: 해 → 오 → 인 (3개)
출처: 애니 (canonStatus: anime)
sourceReference: "Naruto: Shippūden Episode 15 — 이타치 vs 카카시/나루토/사쿠라/치요"
MVP 활성화: MVP 1.5
운용 옵션:
+ 후딜 감소
+ 차크라 효율 증가
+ 실패 페널티 감소

Lv.3 마스터형
시퀀스: 오 → 인 (2개)
출처: 린노쇼 (canonStatus: databook)
sourceReference: "Hiden: Rin no Sho (1st Databook, 2002.7 Shueisha)"
MVP 활성화: MVP 2
운용 옵션:
+ 중간 캔슬/페이크 운용 가능
+ 차크라 효율 추가 증가
+ 위력 안정

Lv.4 전설형 (선택적/숨겨진 컨텐츠 후보)
시퀀스: 인 (1개)
출처: 효노쇼 (canonStatus: databook - 팬북)
sourceReference: "Hyō no Sho (1st Fanbook). 데이터북과는 별개 자료"
MVP 활성화: 후속
주의: 효노쇼는 정식 데이터북 시리즈가 아니므로 별도 표기 필요
```

### 6.3 부분 시퀀스 처리

| 상황 | 게임 처리 |
|---|---|
| Lv.1 시전 중 사 → 미 → 신 → 해까지만 입력 후 멈춤 | 차크라 조형 중단 |
| 중간에 틀린 인 입력 | 술식 붕괴 |
| 너무 오래 다음 인을 못 이음 | 차크라 흐름 불안정 / 캐스팅 취소 |
| 일부러 중단 | 페이크 인 / 술법 캔슬 |
| 다른 시퀀스로 분기 | 다른 술법으로 전환 가능 |

핵심 원칙:

> 부분 시퀀스는 약한 호화구가 아니라 미완성 술식이다.

variant 간 관계 주의:

```text
Lv.1 시전 도중 마지막 3개 인이 "해→오→인"으로 끝난다고 해서
Lv.2 단축형 발동으로 인정하지 않는다.
각 variant는 독립적으로 선언되어 시작되어야 하며,
다른 variant의 부분 일치로 인한 자동 변경은 없다.
```

## 7. 캐스팅 단계와 호화구 매핑

캐스팅 단계는 variant별 시퀀스에 따라 다르게 매핑된다. 아래 표는 Lv.1 표준형(6개 인) 기준이다.

| 단계 | Lv.1 매핑 | 역할 |
|---|---|---|
| 준비 | 사 / Snake | 술법 시작, 상대에게 캐스팅 시작이 드러남 |
| 조형 | 미 → 신 → 해 → 오 | 차크라 성질/형태 구성, 상대가 술법 후보 추측 가능 |
| 응집 | 마지막 인 / Tiger 직후 0.15~0.35초 | 발동 직전 마지막 취약 구간 |
| 발동 | 화염 방사 | 충돌, 회피, 방어, 속성 상성 판정 |

중요 원칙:

```text
마지막 인 입력 즉시 발동이 아니라, 아주 짧은 응집 윈도우를 둔다.
```

MVP 1에서는 응집 윈도우를 주로 시각적 연출과 타이밍 로그로 사용한다. 실제로 상대가 끊거나 카운터하는 전투 로직은 MVP 1.5 이후부터 의미를 가진다.

### 7.1 variant별 응집 윈도우

| variant | 인 시퀀스 | 응집 윈도우 | 의도 | balanceStatus |
|---|---|---:|---|---|
| Lv.1 표준형 | 사→미→신→해→오→인 | 0.25~0.35초 | 읽기 쉬움, 안정적 | prototype_initial_value |
| Lv.2 단축형 | 해→오→인 | 0.18~0.28초 | 빠름, 카운터 난도 증가 | prototype_initial_value |
| Lv.3 마스터형 | 오→인 | 0.15~0.25초 | 매우 빠름, 운용 유연, 카운터 난도 매우 높음 | prototype_initial_value |
| Lv.4 전설형 | 인 | 0.12~0.20초 | 게임 균형 검토 필수, 후속 검토 | prototype_initial_value |

이 수치는 확정 밸런스가 아니라 초기 테스트용 값이다. 차크라 수치와 마찬가지로 테스트 후 조정한다. 특히 Lv.4 전설형은 게임 균형을 크게 흔들 수 있으므로 본격 도입 전 별도 밸런스 검토가 필요하다.

variant별 단계 매핑:

```text
Lv.1 (6개): 준비(1) + 조형(4) + 응집(1) + 발동
Lv.2 (3개): 준비(1) + 조형(1) + 응집(1) + 발동
Lv.3 (2개): 준비(1) + 응집(1) + 발동 (조형 단계 생략)
Lv.4 (1개): 준비/응집 통합(1) + 발동 (별도 검토)
```

## 8. 인식 실패와 실력 실패의 구분

| 실패 유형 | 의미 | 플레이어 피드백 |
|---|---|---|
| Wrong Seal | 다른 인을 맺음 | 기대 인과 다른 인이 감지됨 |
| Low Confidence | 손모양이 애매함 | 손모양이 불안정함 |
| Hands Lost | 손이 화면에서 사라짐 | 양손이 화면에 충분히 보이지 않음 |
| Occlusion | 손가락 가림 심함 | 손가락이 서로 가려져 인식이 어려움 |
| Off Center | 손 위치가 벗어남 | 손을 화면 중앙에 맞춰야 함 |
| Timeout | 다음 인으로 너무 늦게 전환 | 차크라 조형이 중단됨 |

## 9. 속성 상성

```text
화 > 풍
풍 > 뇌
뇌 > 토
토 > 수
수 > 화
```

속성 상성은 절대 승패가 아니다. 술법 랭크, 차크라 투입량, 정확도, 숙련도에 따라 뒤집힐 수 있어야 한다.

```text
최종 충돌 판정 =
술법 랭크
+ 차크라 투입량
+ 인 정확도
+ 숙련도
+ 속성 상성
+ 타이밍
```

본 5속성 상성은 원작에서 카카시가 나루토에게 설명하는 장면 등에서 확인되나, 정확한 데이터북 출처는 후속 검증 항목이다.

## 16. 게임 모드와 MVP 순서

### 16.1 MVP 0: Seal Recognition Feasibility Spike

목적:

```text
호화구에 필요한 6개 인이 웹캠 환경에서 실제로 구분 가능한지 검증한다.
```

검증 지표:

```text
- 인별 precision / recall
- 인별 confusion matrix
- false confirm rate
- unknown 처리율
- 평균 확정 시간
- 조명/손 크기/카메라 각도별 성능
- 사용자 3명 이상에서 재현되는지
```

### 16.2 MVP 1: 호화구 수련장

기능:

```text
1. 웹캠 켜기
2. 손 인식
3. Lv.1 표준형 시퀀스 판정 (사 → 미 → 신 → 해 → 오 → 인)
4. 성공하면 화염 이펙트
5. 실패 원인 표시
   - 최소 구현: Wrong Seal / Timeout
   - 확장 구현: Low Confidence / Hands Lost / Occlusion / Off Center
6. 입력 시간 / 정확도 / 안정성 점수 표시
7. raw replay 저장
8. 사용된 variant 표시 (Lv.1 출처 메타 노출)

MVP 1에서는 Lv.1 표준형 한 가지 variant만 활성화한다.
나머지 variant는 데이터 구조에는 존재하나 게임 내에서는 비활성 상태.
```

### 16.3 MVP 1.5: AI 더미 상대 / Shadow Duel

기능:

```text
1. Lv.1 표준형 + Lv.2 단축형 variant 활성화
2. AI 더미가 두 variant 중 무작위로 시전
3. 플레이어는 사용할 variant를 사전 선택
4. 상대 손 실루엣 + 캐스팅 스트립 표시
5. 카운터 입력은 키보드/버튼으로 단순화
```

Shadow Duel은 다음 네 가설을 분리해서 검증한다.

| 가설 | 내용 | 검증 방식 |
|---|---|---|
| A. 식별 가능성 | 사람은 상대의 인 시퀀스를 시각적으로 구분할 수 있는가 | AI 더미의 손/실루엣을 보고 인 또는 술법 후보 맞히기 |
| B. 재미 가능성 | 상대 손을 보고 대응하는 행위가 재미있는가 | 설문/반복 플레이율/실패 후 재도전 여부 |
| C. 대응 시간 가능성 | 상대 캐스팅 시간 안에 방어/회피/끊기 입력을 완료할 수 있는가 | AI 속도 분포별 카운터 성공률 측정 |
| D. 인지 부하 가능성 | 자기 입력과 상대 관찰을 동시에 처리할 수 있는가 | 내 입력 성공률과 상대 식별률을 동시에 측정 |

AI 더미 변수:

```text
- 인 전환 속도: 느림 / 보통 / 빠름 / 랜덤
- 시전 술법 후보: Lv.1, Lv.2 중 무작위
- 페이크 패턴: 중간 캔슬 또는 다른 술법으로 분기
- 캐스팅 시작 타이밍: 약간 랜덤
```

MVP 1.5의 카운터 입력은 우선 키보드/버튼 입력으로 단순화한다. 목적은 "상대 손을 보고 반응하는 재미"와 "대응 시간 가능성"을 검증하는 것이며, 손 기반 방어/바꿔치기/체술 입력은 MVP 2에서 별도로 설계한다.

### 16.4 MVP 2: 기본 카운터 전투

목적:

```text
호화구 / 방어술 / 바꿔치기 / 체술 끊기의 최소 전투 루프 검증
Lv.3 마스터형 variant 추가 활성화
```

MVP 2 진입 전에 반드시 정해야 할 항목:

```text
1. HP 시스템: 시작 HP, 호화구 명중 피해, 방어 성공/실패 피해 보정
2. 거리/위치 시스템: 근거리/중거리/원거리, 체술 끊기 가능 거리, 호화구 유효 거리
3. 방어술 입력 방식: 원작 인 시퀀스 조사 또는 game_interpretation 처리
4. 바꿔치기 입력 방식: 인 시퀀스 / 전용 제스처 / 키 보조 중 선택
5. 체술 끊기 입력 방식: 키 입력 / 제스처 / 자세 입력 중 선택
6. 최소 전투 루프: 호화구, 방어, 바꿔치기, 체술 끊기
7. Lv.3 마스터형 활성화 시 밸런스 영향 검토
```

### 16.5 후속: Lv.4 전설형 검토

```text
효노쇼 기반 Lv.4 전설형(인 1개)은 게임 균형에 큰 영향을 미친다.
별도 밸런스 검토 후 숨겨진 컨텐츠 또는 챌린지 모드로 도입을 고려한다.
효노쇼는 데이터북이 아닌 팬북이므로 UI에서 출처를 별도 표기한다.
```

## 18. 고증 관리 원칙 (β 원칙)

본 프로젝트는 **모든 공식 매체를 정전(canon)으로 인정**하며, 매체별 차이가 있을 경우 단일 정답을 강요하지 않고 각 매체의 묘사를 모두 게임에 포함한다.

### 18.1 canonStatus 분류

각 술법 시퀀스/메카닉은 다음 상태 중 하나를 가진다.

```text
canonStatus:
- manga              : 만화 본편
- anime              : 애니메이션 (시푸덴, 보루토 포함)
- databook           : 공식 데이터북 시리즈 (린노쇼/토노쇼/샤노쇼/진노쇼)
                       및 팬북 (효노쇼 등)
- game               : 공식 게임 (Ultimate Ninja Storm 시리즈 등)
- fan_interpretation : 팬 커뮤니티 해석. 게임 도입 시 명시 필요
- game_interpretation: 본 프로젝트 자체 게임 디자인 해석. 게임 도입 시 명시 필요
```

### 18.2 β 원칙

```text
원칙 1: 매체별로 다르게 묘사된 술법/메카닉은 모두 정전으로 인정한다.
원칙 2: 어느 한 매체의 묘사를 다른 매체보다 우선시하지 않는다.
원칙 3: 각 variant는 canonStatus와 sourceReference 메타데이터를 보유한다.
원칙 4: 게임 내 도감/툴팁/상세보기에서 출처가 노출된다.
원칙 5: 데이터북과 팬북은 같은 databook enum을 쓰되 sourceReference로 구분한다.
원칙 6: fan_interpretation/game_interpretation은 게임 내에서 명시적으로 구분 표기된다.
```

### 18.3 검증 단계

각 술법/메카닉은 다음 검증 단계 중 하나를 가진다.

```text
verificationStatus:
- verified           : 1차 자료(원본 매체) 직접 확인 완료
- cross_referenced   : 위키 등 2차 자료 교차 검증 완료, 1차 미확인
- claimed            : 출처가 주장되었으나 미검증
- needs_research     : 추후 조사 필요
```

본 v6 시점에서 호화구의 술 5가지 variant는 모두 `cross_referenced` 상태이며, 본격 배포 전 본인이 매체 원본을 직접 확인하여 `verified`로 승급할 것을 권장한다.

### 18.4 매체별 충돌 시 처리

```text
1. 모든 묘사를 variant로 보존한다.
2. 게임 레벨/MVP 활성화 일정은 게임 디자인 판단으로 결정한다 (출처 우선순위가 아님).
3. 도감에서 모든 출처를 동등하게 표시한다.
4. 플레이어가 자신이 사용한 variant의 출처를 확인할 수 있어야 한다.
```

## 19. 최종 요약

현재 개발 순서:

```text
MVP 0: 호화구 6개 인 인식 가능성 검증
MVP 1: 호화구 수련장 + raw replay (Lv.1만 활성)
MVP 1.5: AI 더미 상대 / Shadow Duel (Lv.1 + Lv.2 활성)
MVP 2: 기본 카운터 전투 (Lv.3 추가 활성)
후속: Lv.4 전설형 검토
```

현재 1차 구현 목표:

```text
대상 인:
사 / 미 / 신 / 해 / 오 / 인

핵심 판정 (Lv.1 표준형):
정상 발동: 사 → 미 → 신 → 해 → 오 → 인
중간 중단: 술법 미발동
중간 실패: 술식 붕괴
의도적 중단: 페이크/캔슬 가능

데이터 구조:
호화구 5가지 variant 모두 정의 (Lv.1~Lv.4)
MVP 1에서는 Lv.1만 활성, 나머지는 비활성 상태로 보유
```

검증 진행 상태:

```text
검증 완료 (cross_referenced):
- 호화구의 술 5가지 시퀀스 variant

후속 검증 항목:
- 차크라 시스템 원작 설명
- 5속성 상성 데이터북 출처
- 12지 인의 정확한 명칭과 영문 표기
- 인 12지 매핑의 원작 출처
- 원작 닌주츠/타이주츠/겐주츠 3대 분류와 §3의 7개 분류 간 매핑
- 분신술/바꿔치기/체술/환술의 매체별 차이
```
